# 两台 Mac 与手机共用记录

当前稳定版为0.5.117。已有设备输入与回执机制尚未实现两台 Mac 和手机完整接续对话、修改与确认，不能视为完整跨端体验。手机即时记录灵感、其他设备接续处理是后续方案的核心目标；整体结构仍待设计与审阅，真实多设备暂不接入。

## 现有机制与限制

设备分工与设备随手记已随0.5.103发布。同步服务负责传文件，常开的 Mac 负责把输入处理成任务、日记等记录；另一台 Mac 可保存原始随手记并查看同步回来的回执。插件仍只在桌面运行，手机使用 Obsidian 和系统听写。真实两台 Mac 与安卓的配对、后台同步及正常使用仍须实机核对，本机双副本演练不代替实机验收。

0.5.101曾发现首次设备设置后的即时回退兼容问题，修复已随0.5.103交付。只有设备配置完全提交或恢复后，才将恢复日志改成旧版可读的结束标记，完整审计和撤销快照继续保留；切换程序前还会拒绝旧版不能读取的日志。0.5.112在Obsidian 1.12.7与1.5.8虚构库各通过51项检查，包含首次设置后即时回退0.5.100和业务回退0.5.111。下文配置仅作为已有机制的隔离演练说明，不是完整跨端方案的接入指引。

## 同步路线

两台 Mac 和安卓可以使用无需订阅的 [Syncthing](https://syncthing.net/) 传输同一个记录库。macOS 有[项目提供的桌面集成](https://syncthing.net/downloads/)，安卓使用[官方文档列出的社区客户端](https://docs.syncthing.net/users/contrib.html#android)，例如 Syncthing-Fork 或 BasicSync。安卓客户端属于独立维护的项目，不能把它当作官方客户端；实际安装与后台运行要在手机上核对。

有 Obsidian Sync 的用户也可以沿用它。只选一种服务管理同一个库，先完成处理端配置和首次同步，再打开另一台的 LifeOps；离线时只能看到本机已有内容，不能承诺立即最新。

两端都排除 `.obsidian`、`.git`、`.trash` 和 `.DS_Store`。尤其不要同步 `.obsidian/plugins/lifeops-assistant/data.json`，其中可能包含模型配置和密钥。插件分别安装，本机身份保存在应用本地存储；共享文件只携带记录目录及处理端标识。Syncthing 的忽略规则需要分别设置，规则文件本身不自动传播，见[官方忽略说明](https://docs.syncthing.net/users/ignoring.html)。

在每个设备的 Syncthing 文件夹忽略设置中分别保存：

```text
/.obsidian
/.git
/.trash
.DS_Store
```

2026-11-21 已在一台 Mac 的两个独立 Syncthing 进程中实际验证双向文件、80 MiB 附件、设置排除及离线重开；联合 LifeOps 的写入模块验证原文签收、一次入账、回执返回、重复扫描和按条撤销。所有内容均为虚构，通信仅限本机回环。这证明了该传输与模块的组合，不是实际第二台 Mac、安卓、电池后台策略或互联网连通验收。

同步不会替代独立备份。连接真实库前先备份完整文件夹，再检查两端没有其他服务同时同步同一目录。

如果两台设备离线时都被选为处理端，Syncthing 可能保留名为 `设备协作.sync-conflict-….json` 的竞争副本，见[官方冲突说明](https://docs.syncthing.net/users/syncing.html#conflicting-changes)。LifeOps 检测到后会暂缓处理和提醒，界面仍可打开，原始随手记仍可保存并同步；不会自动选择或删除任一副本。先停止两端处理，备份整个库并核对保留下来的设置和业务记录，确定唯一处理端后再恢复。只移动冲突副本不能代替业务记录核对。

## 配置顺序

先备份整个库，所有桌面更新到已验收、含设备协作的同一版本。结构化任务和习惯文件由处理端写入，另一台 Mac 使用设备随手记。不要在两个离线设备上直接编辑同一任务 JSON、任务看板或同一篇日记。

1. 在常开的 Mac 选择“这台负责处理”。已有记录保留，本机身份保存在应用本地存储中。
2. 连接一种同步服务并完成首次同步。Syncthing 通过双方确认的设备标识共享库文件夹，两端配置上述忽略规则。使用 [Obsidian Sync](https://obsidian.md/sync) 则连接同一远端库，开启“其他文件类型”以同步 JSON，关闭第三方插件设置同步，见[官方设置](https://obsidian.md/help/sync/settings)。LifeOps 不代为订阅、登录、配对或上传真实资料。
3. 第二台 Mac 下载同一库，等首次同步完成，再启用同版插件并选择“这台只记录并同步”。不要在尚未同步的另一台也设置处理端；当前版本没有自动接管功能。
4. 第二台 Mac 点“随手记”，输入一句话或用系统听写。保存后先显示“原始记录已保存在本机”。常开 Mac 处理后，在“设备随手记回执”核对入账。确认高风险修改和撤销已保存记录，目前集中在常开 Mac 的回执窗口。
5. 手机打开同一库，在 `输入/手机随手记.md` 每行写一条并换行。常开 Mac 的 LifeOps 设置中启用“手机随手记”，在“手机随手记回执”核对。手机无需模型密钥。

首次选择处理端时如果应用中途退出，重新打开同一台 Mac，再选择“这台负责处理”即可重试。本机只恢复自己尚未完成的首次设备设置；若共享记录被修改、属于另一台设备或存在其他待恢复业务，会保留资料并提示核对。

断网时输入留在本机；参与端完成同步，且处理端的 Obsidian 正在运行后才会更新结果。同步中的半份输入会停下来核对；重复同步不作为新任务反复执行。原始输入保留，不要修改同一设备 JSON 来纠正已处理请求，请先在处理端更正或撤销，再提交新记录。

## 首次验收（约 5 分钟）

当前稳定版的设备随手记已接入整批新建：一段明确要求保存的计划最多20项，共用桌面排程，按一条原始输入完整保存或回退，并显示实际新增/已有数量及完整回执。重复同步和回执丢失按原操作核对；本条可整批撤销，其他已有任务保留。离线延迟处理时保留录入时的日期，已经过去的日期不倒填时段。多种修改混合或对象不明时仍需到处理端补充。桌面工程已交付，真实手机仍待实机验收。

11月21日补充真实回环传输：一段五项计划在处理端实际新增四项、沿用一项已完成任务；完整回执返回另一副本。重复传输不再调用模型，整批撤销保留原已完成任务；离线输入恢复同步后保留原日期且不倒填过去时段。使用虚构模型结果驱动生产模块，两个 Syncthing 进程正常退出；没有连接本人资料、实际第二台 Mac 或安卓。进程中断恢复另有子进程强制终止测试覆盖。

第二台 Mac 保存“明天提醒我整理虚构蓝纸”。常开 Mac 确认只出现一个任务，原文不变。重复同步和重开后仍只有一个；撤销这条，其他记录保留。手机也写一条以“虚构”开头的任务，换行后核对一次回执。断网保存一条，恢复网络并完成同步后核对原日期和一次入账。

本地双副本和界面演练不能替代真实两台 Mac、安卓和云端同步验收。未完成实机步骤时保留“同步准备就绪、实机待验”。Obsidian Sync 对一般文件按修改时间保留一份，不能假定业务记录会自动合并。[官方冲突说明](https://obsidian.md/help/sync/troubleshoot#Conflict%20resolution)。

## 切换与回退

设备身份不随库文件同步。重装应用、清空应用存储或更换电脑时，保留库和备份；遇到已有其他执行端时，本版拒绝直接接管。更换执行端需先停止旧端，再由维护者迁移。

回退前等保存结束，保留整个库和应用本地存储。旧版不认识设备分工，只在原处理端运行；其他设备停用旧版 LifeOps，继续保留待处理原文。

## 开发者复验

手动下载并校验 Syncthing 可执行文件后运行：

```sh
node scripts/eval/sync-transport-runner.mjs --binary /absolute/path/to/syncthing
LIFEOPS_SYNCTHING_BINARY=/absolute/path/to/syncthing npx vitest run --config vitest.sync.config.mts
```

两条命令只创建新的虚构临时库，不接受现有库路径、不自动下载程序、不安装系统服务。默认关闭外部发现、中继、NAT、统计和升级，监听只在回环地址；完成后正常停止子进程，输出临时库中的 `result.json`。常规测试和 CI 不会自动运行这个需要外部二进制的场景。
